## Remaining limitations

- The initial production test used locally available seed IDs that are hidden on VPS; creation correctly rejected them. Verification subsequently used published catalogue records.
- Asking for less salt on a pastry without added salt returned a generic no-change clarification. That response needs better wording; it was not counted as a successful modification.
- The earlier 40-call reviewer diagnostic had two structured-output failures. Evidence checks improve coverage but do not prove semantic correctness for arbitrary requests.
- Broad global-constraint changes involving locked dates, profile overrides and multiple dishes still need dedicated real acceptance. This is not a claim that the entire original test plan passed.
- This release was a source-package deployment, not a new Git commit; the deployed Git HEAD alone does not identify the running backend.
